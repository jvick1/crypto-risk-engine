# Roadmap

Educational project — not investment advice. Each phase lands on its own feature branch, is reviewed, then merged to `main`.

| Phase | Scope | Status | Done when |
|---|---|---|---|
| 0 | Cleanup: remove committed `__pycache__`, `.gitignore`, pinned `requirements.txt`, docstring/help fixes, `data/backtest` auto-create, `--no-verbose`, pytest skeleton, README install/flags | **Done** — merged in PR #1 (`ae194cb`) | Merged to `main`; tests pass |
| 1 | Kupiec POF (chi2 df=1), Christoffersen independence (df=1) and conditional coverage (df=2) tests; per-method summary | **Done** — merged to `main` (`7eae914`) | `--backtest` prints and saves `data/backtest/{coin}-backtest-summary.csv` with breaches, expected, breach rate, LR stats, p-values, reject-at-5% flags; edge cases (zero breaches, no transitions) return finite values; hand-checked unit tests pass |
| 2 | Student-t robustness: bound df (nu > 2), fit fallback, CVaR guard | **Done**: merged to `main` (`7eae914`). Backtest effect (BTC, alpha 0.05, 252-day window): the 2.01 df floor binds in 1,064 of 4,179 rolling windows (raw fits as low as 1.23); Student-t breaches went from 237 to 241 and the Kupiec p-value from 0.051 (pass) to 0.026 (reject at 5%). Full-sample VaR/CVaR unchanged. Floor kept by design (df <= 2 means infinite variance). | Fitted df always > 2; a failed/degenerate fit falls back (e.g. to Normal) with a warning; CVaR never diverges or returns NaN/inf; tests cover each case |
| 3 | PyMC Bayesian Student-t on the full sample, `--methods bayes` | **Done**: merged to `main` via PR #2 (`fa47477`). `src/bayes.py`: priors mu ~ Normal(0, 0.5 s), sigma ~ HalfNormal(s), nu = 2 + Gamma(2, 0.1) (s = sample std); VaR/CVaR per posterior draw (closed-form t) with 94% HDIs, plus the exact posterior predictive VaR/CVaR; R-hat and bulk/tail ESS with warnings. BTC live run 2026-11-12 (alpha 0.05, 4,439 returns, 4 chains x 1,000 draws, seed 42): Bayes predictive VaR -0.0485 (94% HDI -0.0504 to -0.0466), CVaR -0.0939 (HDI -0.1019 to -0.0870); nu posterior mean 2.28 (HDI 2.10 to 2.45) vs MLE df 2.22; max R-hat 1.002, min ESS 2,025, 0 divergences; sampling about 5 s, full run about 7 s. | Weakly informative priors with nu > 2; VaR/CVaR from the posterior predictive with credible intervals; R-hat and ESS reported (warn if R-hat > 1.01); seeded and reproducible; tests pass |
| 4 | Rolling Bayesian backtest | **Done on branch** (`feat/phase4-rolling-bayes-backtest`), awaiting review. `src/rolling_bayes.py` adds a `bayes` backtest method (`--backtest` with `bayes` in `--methods`): `--bayes_engine mcmc` (Phase 3 Student-t, compiled once, refit every `--refit_every` k days, default 21, warm-started from the previous posterior means, 2 chains x 500 draws + 500 tune, R-hat / ESS / divergence checks per refit, failures counted) or `conjugate` (Normal-Inverse-Gamma, closed-form t predictive, refit daily); each refit uses only the window ending the day before the refit day; MCMC fits cached in `data/cache/` (gitignored) keyed by window data + settings + seed + init. BTC run on the committed returns CSV (2014-09-18 to 2026-02-28, 4,182 returns; 3,930 forecast days 2015-05-28 to 2026-02-28; alpha 0.05, window 252; expected breaches 196.5): Normal 199 breaches (5.06%), Kupiec p 0.855, Christoffersen ind p 0.0013; Student-t 234 (5.95%), p 0.0076, ind p 0.0003; Historical 214 (5.45%), p 0.206, ind p 0.035; Bayes conjugate (k=1) 199 (5.06%), p 0.855, ind p 0.0013, same breach days as Normal (VaR within 0.00004 of Normal: Normal likelihood); Bayes MCMC (k=21, seed 42) 248 (6.31%), p 0.0003, ind p 0.0005, 10 of 188 refits failed diagnostics (all R-hat 1.010-1.020; 0 ESS, 0 divergence failures). For context, a Student-t MLE refit on the same k=21 schedule gives 239 breaches (vs 234 daily), so about 5 of the extra breaches come from the stale posterior and the rest from the Bayes predictive VaR sitting slightly above the MLE t VaR (mean +0.0006 on refit days; posterior median nu 3.2). Runtime: Bayes part 0.7 s conjugate, 178 s MCMC cold cache, 0.6 s MCMC fully cached; whole backtest about 92 s without MCMC (Student-t MLE loop), 270 s with it. Normal / Student-t / Historical columns identical to `main`. | Refit every k days (configurable), warm start from previous posterior, conjugate Normal-Inverse-Gamma fast path, cached fits; output feeds the Phase 1 summary; runtime documented |
| 5 | README update | Planned | README documents all methods, flags, outputs and caveats, and matches the code |
| 6 | Performance profiling: detailed timing logs plus a pipeline workflow diagram | Planned | Each pipeline stage (data pull, returns, fits, risk metrics, backtest loop, plots) logs its wall-clock time through Python `logging` with a `--log-level` / `--profile` flag; a timing summary is printed and saved per run; `docs/APP_FLOW.md` diagram is labeled with measured stage times from a real run; bottlenecks are ranked |
| 7 | Speedups chosen from the Phase 6 results (scope left open until profiling is done) | Planned | Candidates include parallelizing backtest refits (multiprocessing or threads), caching raw data for popular coins such as BTC and pulling only the new rows since the last run (delta update), and caching fits/results; each change is benchmarked before and after on the same run, and backtest output stays identical unless a difference is documented |
| 8 | Simple UI dashboard | Planned | CLI flags (coin, vs currency, alpha, window, methods, backtest) become on-screen inputs; the run shows live progress stage by stage following the Phase 6 workflow diagram (for example, a preview of the downloaded data, then "working on fits", and so on); all charts (PDF overlay, QQ, left tail, rolling VaR) and the backtest summary display on screen; built with App / UI; no change to the core math |
